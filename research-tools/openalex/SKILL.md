# OpenAlex 来源适配规范

这是第一次检索任务的 OpenAlex 来源说明，不是全文阅读器，也不是创新性证明器。

适配器应：

1. 接收统一契约中的研究兴趣、上下文、年份、文献类型、来源策略和数量限制。
2. 生成可复现的 `query-plan.json`，保存查询、source 状态、分页和时间信息。
3. 通过合法公开 API 获取元数据与摘要，保留标题、作者、机构、期刊/会议、年份、引用量、摘要、DOI、来源链接和来源状态。
4. 使用 cursor 分页，并按 DOI、其次 OpenAlex ID 去重；对 429、5xx 和网络错误执行有界重试。
5. 将结果、候选方向和 manifest 转换为 `contract.md` 的统一文件格式；候选新颖性标记为 `candidate_pending_verification`。

会议 × 年份检索必须使用经核验的 source ID，并将每个会议/年份作为可追溯查询记录。OQL 只在用户明确要求时使用；远端验证未通过时不得把本地计划写成已验证结果。

OpenAlex 适配器不下载 PDF、不生成 BibTeX、不负责第二阶段核心文献包，也不在浏览器中直接请求 API。没有 source ID、没有命中、来源过宽或请求失败时，写入 manifest 错误/警告并保留状态，不用宽泛查询掩盖失败。

本仓库未迁入实际 Python 脚本；实现应放在受控后端服务中，并通过统一任务接口供前端读取。
